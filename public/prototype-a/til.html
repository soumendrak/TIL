I've been wiring SigNoz into our agent runtime this week. Most of the LLM "observability" demos online treat a single chat call as the unit of work, which doesn't survive contact with a real agent loop — tools nest, retries fan out, and the wall-clock latency you actually care about is the one the human waited for.

The trick

OpenTelemetry's new gen_ai.* semantic conventions give you a vocabulary that SigNoz, Arize, and Langfuse all understand out of the box. Wrap the model call in one span, each tool call in a child span, and let the SDK propagate context:

with tracer.start_as_current_span(
    "openai.chat",
    attributes={
        "gen_ai.system": "openai",
        "gen_ai.request.model": "gpt-4o-mini",
        "gen_ai.usage.input_tokens": prompt_tokens,
    },
) as span:
    resp = client.chat.completions.create(...)
    span.set_attribute("gen_ai.usage.output_tokens", resp.usage.completion_tokens)

What you get

  • A real waterfall in SigNoz — tool calls render under their parent.
  • Token usage as a first-class metric you can chart per model.
  • Error spans that capture the prompt, not just a 500.

The whole change was ~40 lines. Cheapest observability win I've had this quarter.
